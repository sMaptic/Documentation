### Process
When a file is imported into `user://custom_levels/`, a list refresh is called. Because the map is new, it has yet to be loaded into memory, and so a load is attempted. This also happens if the game loads and the map is already installed. The function that loads packs is detailed below:
```gdscript
func load_packs(data : Array) -> void:
    # iterate through valid level files and load them into res://
    var loaded_count := 0
    for level in data:
        var path = level["path"]
        if _loaded_packs[path]:
            continue
        if path.is_empty() or not FileAccess.file_exists(path):
            Log.warn("Skipping unavailable map resource pack \"%s\"" % [path])
            continue
        if not ProjectSettings.load_resource_pack(path):
            Log.warn("Failed to load map resource pack \"%s\"" % [path])
            continue
        _loaded_packs[path] = true
        loaded_count += 1
    Log.say("Loaded %s map resource packs" % [loaded_count])
```
The function `ProjectSettings.load_resource_pack()` is a built-in function in Godot. It takes the contents of a `.zip` or `.pck` file, and merges them into the root of the game file tree in memory. Any files that already exist are replaced, and any that do not are added. This does not modify the game executable, this modification is memory-only and is gone after the game closes. This is the recommended method for loading custom content by the Godot documentation.

Due to the fact that `load_resource_packs()` overwrites existing files, imported maps need to be contained within their own map root folder to avoid modifying integral files. This is why all of the previously outlined validation checks and file stripping were required.
### Handling Additional Files
As mentioned in 3.b., certain non-selected files are exported and may not be stripped during runtime. These files are handled as follows:

- `uid_cache.bin` and other similar cache files are required for maps to function correctly. These files, as far as I can tell, are handled implicitly by `load_resource_packs()` (presumably via being merged) and do not require manual handling. This is still being investigated however, and this information may change.
- `project.binary` DOES fully overwrite its original upon import, however Godot only references this file during load time, and does not interact with it beyond that point. This means that the file can be safely overwritten without harm. 
- The mandatory contents of `art/textures/` are similar to `project.binary` in that they are not typically referenced beyond runtime. The boot splash is only used during load time, and the anon icon is used for the window icon, which is also only loaded into memory at load time to the best of my knowledge.

Despite being effectively harmless, `project.binary` and `art/textures/` will both be stripped at import to prevent any unpredictable behavior.
### Potential Changes
- In future, imported maps will only be loaded into memory when opened. This would help reduce excessive memory usage for users with many imported custom maps that may only want to play a limited number during a session.
- When fully sandboxed in a future update, maps will (hopefully) be unable to touch vanilla game resources entirely outside of referencing. As of right now, whilst vanilla resources cannot be replaced via to validation and file stripping, they can be modified programmatically.
