### Map Export
To export from the Godot editor, you need to ensure that all requirements outlined in the Criteria section of 2.b are met before exporting in order to ensure compatibility with import validation checks. Then, follow these steps:

1. Click the Project dropdown in the top left of the editor window, then select Export in the dropdown menu.
2. In the new window, if no preset is available, click Add at the top of the presets list and select Windows Desktop.
3. Switch to the Resources tab and change the Export Mode to the second option from the bottom "Export all resources in the project except resources checked below"
4. In the file tree, select the root folder, and then navigate to the folder of the level you would like to export and uncheck it, as shown below. (Collapsing folders until you reach the `custom_levels/` folder is generally optimal.
 ![[export_window_example.png]] 
 5. Click "Export PCK/ZIP..." in the window footer and save to your directory of choice. Always save the file with the .zip extension, and not .pck, as it is not currently supported. The file name does not matter, so pick something recognizable to the end user. 
### Publishing
To publish a new or updated map to the official map index, you need to create a pull request into in the main MapIndex repository. To start, you first need to create a fork of the repository. If you already have a fork, skip this first set of instructions. Otherwise, follow these steps to begin:

1. Ensure that you have created a [GitHub](https://github.com/) account for this process and are signed in. Without an account, you cannot fork the repository, nor create pull requests.
2. Head to the [MapIndex repository](https://github.com/sMaptic/MapIndex) and find the button in the top right of the page (above the sidebar) that says "Fork". Click this to open the fork creation menu. 
3. By default, a fork shares the same name and description as the initial repository, but this can be changed to whatever you like. Ensure that the box asking to copy the default (main) branch only is ticked. Then, hit "Create Fork" to create your repository fork.

Now that you have a fork of the repository, it is time to add your map and icon to it. If you already have a map in your fork that you would just like to update, remove the old `.zip` file and replace it with the new one. If not, follow these steps:

1. Create a folder somewhere on your PC that shares a name with your map ID. Then, place your exported `.zip` file, as well as your `icon.png` that you created in 2.a. into your folder. This is your index entry, and both of these files are required for a map to be accepted onto the index.
2. Open your forked repository on GitHub, go to the "Code" tab, and open the `index/` folder. Click "Add file" in the top right of the page, and select "Upload files". (If you are doing this in a local repository clone, do this via a file explorer of your choice)
3. Within the upload menu, drag the folder you created in step 1 into the file drop zone. Both files should upload and now be listed below. 
4. Choose a suitable name for your commit. You should write something like "index: added my_map" or "index: updated my_map to version 0.1.1" to communicate exactly what change you are making to the index. Any additional context in the description is appreciated and may help your submission get approved faster.
5. Commit your changes! The new files should now appear in the index folder of your forked repository.

Once your commit has been pushed, you are now ready to create a pull request to have your map added to the main index:

1.  Open your forked repository on GitHub, go to the "Pull requests" tab, and click "New pull request" in the top right of the page. This should open a new pull request draft with your commit already selected.
2. Confirm that your changed files are in the correct `index/<map_id>/` folder before continuing. No other files should be in the changed files list in your request.
3. Hit "Create pull request" to finalize your changes and send the request to the main MapIndex repository for review. Please be aware that all maps are checked for malicious content before being approved, so may take time to be added to the index officially. 

If a requested map misses any required criteria, does not meet a minimum bar of quality, or contains any potentially harmful content, your request may be rejected. If this is the case, but changes can be made to allow the map to meet the criteria above, you may be contacted with requested changes that will need to be added to your fork. Once modified, you can update your pull request on its page to match the latest commit on your fork, and it will be re-reviewed.

If you are stuck on any part of this process, please contact @theidiotcreature on discord for more information regarding publishing to the map index. 
### Potential Changes
- A future map development plugin should simplify the export process. This would automatically set up export preferences and simplify the process of selecting the level folder to export to a dropdown or similar menu.
- In future, developers that want to publish maps officially may need to save the raw files from their level folder and share them with me (@theidiotcreature) or another sMaptic moderator in order to be accepted onto the official map index, so that any moderator of the list can verify that they correctly compile to the provided map zip and do not contain any malicious files. This additional export process will also be automated eventually, using the aforementioned plugin to export the raw files alongside the binary exported files.
- The process of uploading to the map index is currently quite tedious. In future, an alternative to pull requests should be considered.
