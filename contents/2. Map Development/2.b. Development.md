### Rules of Thumb
When developing your map, you are almost entirely free to do anything within the bounds of the game. Want to make your main scene a level browser/hub world and have many smaller levels accessible from within? Want to create a crazy boss-fight with a myriad of unique set pieces and behaviors? Want to import a map from another game and load it into SNAPTIC just to explore it in a new way? All of that is possible! 

It is imperative, however, that you understand the following design rules when developing to keep the map functional, minimal, and fun! Always think ahead about whether something you plan to add or change follows these guidelines:

- When you want to add something from a vanilla map, don't create a new asset for it! Drag and drop it from the file tree, or copy it from an existing scene (useful if you want all the inspector options preset and a script already attached). 
- If you need to make a slight change to a vanilla object, check if an inspector option allows you do so without creating a duplicate of the assets for an object. If you need to make a programmatic change, have the new script extend from the existing script rather than copy-pasting the contents wherever possible.
- If you need to import a new asset (texture, sound, etc.), or create a new resource (scene, script, etc.), always import it into your map root folder or a subfolder within. This is due to resources outside of the map folder being stripped at import. For example, textures stored in `res://art/textures/` will not load, but those stored in `res://custom_levels/my_map/textures/` will remain in the stripped file.
- Don't try and interact with anything outside of your level when scripting! Interactions with something like the user's filesystem, or the base functionality of SNAPTIC, are very unsafe! Ambitious ideas are good, but those sorts of interactions are what the GDPatch modding API is for!
- Avoid potentially inappropriate materials in your maps. This includes everything you'd expect to be classified as inappropriate, such as NSFW, gore, etc.

**TIP:** Keep your level folder clean! Messy maps are hard to maintain, read, and update, so keeping files organized is important! Make sure to create folders for different scenes, categories of imported assets, etc. and remove outdated content to reduce bloat.
### Criteria
Maps developed for sMaptic must adhere to a specific set of criteria in order to pass the validation checks at import. The criteria are as follows:

- The root folder of the map must follow the structure of `res://custom_levels/my_map/`. Any other folder structure will fail to detect the level.json file, and imports will fail. 
- All non-vanilla files (textures, scenes, scripts, etc.) must be in the map root folder or a subfolder within it. Any assets outside of the map root folder will be stripped at import, and so will fail to load. 
- `level.json` and the main scene file must both exist, be named correctly, and be placed in the map root folder.
- `level.json` must contain a valid ID that is in lower_snake_case and matches the name of the map root folder and the main scene, and does not conflict with any vanilla level IDs or folders.
- There must only be one file named `level.json` in the map folder hierarchy.
- This list is subject to change! Keep an eye out for alterations made to this criteria so that your map remains usable!

**TIP:** Do NOT tamper with the exported zip file unless you know what you are doing. Certain files are crucial to an imported map remaining functional, and should not be altered or removed. Additionally, this makes verifying that an exported map zip is safe much more difficult. Any changes that you would like to make should be made in-editor and the zip should be re-exported.
### Potential Changes
- To give maps a way to save data externally without breaking the rule of 'no external interaction', I plan to implement a save data API to ensure that such saving and loading is guaranteed to be handled safely.
- I am considering allowing players to use multiple LevelName entries per map to allow for multiple scenes to be implemented.
- A future map development plugin may allow for users to see a list of commonly used vanilla level assets and easily import them directly into a scene, to avoid the slowdown caused by rapidly switching between scenes.
