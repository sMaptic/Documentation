### Recovery
To create a map, you need a decompiled copy of the latest version of the SNAPTIC Demo. If you already have a functioning decompilation, read ahead to Map Setup. To obtain a decompilation, you should follow these steps:

1. Download [Godot RE Tools (GDRE)](https://github.com/GDRETools/gdsdecomp), unzip and open the app.
2. In the RE Tools dropdown, select "Set encryption key..."  and enter the game's encryption key. If you don't know the key, you can find it yourself using the GDPatch [pckdec](https://gdpatch.github.io/pckdec/) tool, or ask in the [SNAPTIC Modding](https://discord.gg/PgfbejJ8D) discord server.
3. In the RE Tools dropdown, select "Recover Project..." and select "snaptic.exe" from the SNAPTIC Demo local files. To find these files, open the game page in your steam library and click "Settings Icon > Manage > Browse local files".
![[browse_local_files_example.png]]
4. Ensure that all resources are checked, and that "Full Recovery" is selected. Select a destination for the extraction in the bar below the file tree, then click Extract at the bottom of the window. Select "Yes" in the prompt that appears asking about extensions, and wait for the application to finish decompiling.
5. Open [Godot 4.7.1](https://godotengine.org/download/archive/4.7.1-stable/) and select "Scan" in the top bar. Navigate to the folder you saved your decompilation to and select it to open the recovered project.
6. To test if your decompilation was successful, open your recovered project and click the play icon in the top right once loaded. This should launch the game into the main menu.
7. By default, Mirraxis crashes the game when loaded from a recovered project. To change what level launches when "Play" is pressed, open `res://game/game.tscn` in the file tree panel (bottom-left) (this should already be open in a fresh project) and select the main "Game" node in the scene tree panel (top-left). Once selected, open the "Starting Level" dropdown in the inspector panel (right) and choose either "Movement Playtest" or "Test Room". You should now have a mostly functional recovered project!

**TIP:** If you are having issues with the Godot editor crashing, try enabling Editor > Editor Settings... > Interface > Editor > Display > Single Window Mode. This embeds all external windows within the main window and reduces the strain of large projects on older systems significantly.
![[single_window_mode.png]]
**TIP:** Holding space when opening the game or playing a stage that has an intro cutscene will skip that cutscene. Useful for decreasing time between tests.
### Map Setup
Maps follow a specific format for ensuring that imported maps do not conflict wherever possible. When importing maps, the loader performs validation checks to ensure that the criteria detailed here and in 1.b are followed correctly. If not, imports will fail and maps will not load, so be sure to follow these steps carefully when setting up your map:

1. Create the folder `custom_levels/` in the root of the file tree and create a new folder within it. This is your map root folder, and must follow lower_snake_case in naming scheme, for example: `res://custom_levels/custom_map/`. This folder name will be hereon referred to as your 'map ID'.
2. Within your map root folder, create a text file named `level.json`, which will contain important information about your map. Open your `level.json` file and copy the format in the example below, but substitute the contents with your level information. The "id" field is required and should be the same as your map ID (folder and scene file name), so that the loader knows which scene file to load. All other fields besides "id" are not required for a map to successfully import, although it is highly recommended to include them as they will be displayed to the player on the imported maps list, and are required for map index submissions.
```json
{
	"id": "custom_map",
	"name": "Custom Map Name",
	"version": "1.0.0",
	"authors": ["Me", "Other Person"],
	"description": "A short description around 50 characters long at most"
}
```
3. Also within the map root folder, create a scene file named identically to your map ID and set the root type to "3D Scene". This `.tscn` file will contain your main scene which will be loaded into when the user loads your map. Then, copy the following nodes from an existing level scene into your new main scene:
	- Player
	- WorldEnvironment
	- AbsoluteFloor (or some other solid object)
4. Locate `res://autoloads/level_loader/level_loader.gd` and open it. At the top of the file should be an enum called LevelName and a constant Dictionary named LEVEL_PATHS. In the LevelName enum, add a new entry that is your map ID in full uppercase. In LEVEL_PATHS, add a new entry with the key as your new LevelName entry, and the value as the path to your main scene. An example is shown below:
```gdscript
enum LevelName{
	...
	CUSTOM_MAP,
}

const LEVEL_PATHS: Dictionary[LevelName, String] = {
	...
	LevelName.CUSTOM_MAP: "res://custom_levels/custom_map/custom_map.tscn", 
}
```
5. Save `level_loader.gd` and your main scene, and reload your Godot project. This should add your new enum entry to the Starting Level dropdown in the inspector for the root node of `game.gd` as mentioned in step 7 of the Recovery guide. To test whether your map loads correctly, change Starting Level to your entry, then start the game and press play to load into your scene.

**OPTIONAL:** If you wish to add an thumbnail image to your map, add an image file to your level folder called `icon.png` which should contain a square image that is at least 96x96 pixels. In future, level thumbnail images may be rendered larger in the imported map list or map browser, so a size of approximately 500x500 or larger is recommended. Images will be scaled automatically to the correct size. This is required for map index submission.

### Potential Changes
- Requiring map developers to assign themselves a namespace may also further reduce collisions between custom levels. For example: two developers using `res://custom_levels/my_map/` would mean that users that install both maps would experience collisions, but if namespaces were enforced, both maps would instead occupy `.../ziblo/my_map/` and `.../blarget/my_map/` respectively, which avoids any file collisions.
- A future map development plugin would ideally automate the map setup process, with the exception of setting things like map ID and other info.
- A template map would be more convenient for developers than a manual setup process. This is something to consider as an addition to the aforementioned plugin, or as a standalone download.
